### Added

- Settings page (v2): tabbed layout with five sections — Views, Project,
  Schedule, Tags, Links. All project.md fields are now editable from the UI.
- Settings Views tab: enabled/disabled collapsible groups, search filter,
  check all/uncheck all bulk actions.
- Settings dirty form tracking: snapshot-based comparison auto-detects when
  values revert to their original state. Dirty tabs show a warning dot and
  `beforeunload` prevents accidental navigation.
- OpenAPI (Scalar): vendored API reference at `/api/v1/reference` with
  documented schemas for all Settings, Milestone, and Portfolio endpoints.
- OpenAPI model names: all Zod schemas now register `.openapi("Name")` so
  they appear in the Swagger Models section (Task, FeaturesList,
  UpdateProjectConfig, ProjectLink, etc.).
- MCP server (v2): scaffold at `/mcp` with 7 milestone tools as thin
  wrappers over shared services. Service-first architecture with unified
  Zod schemas.
- Sidebar: dynamic navigation built from enabled features list. Toggling
  features in Settings immediately refreshes the sidebar.
- Eisenhower domain (v2): full stack — types, repository, service, API
  CRUD at `/api/v1/eisenhower`, SSR matrix view at `/eisenhower`, detail
  page, SSE live swap, and MCP tools (`list_eisenhower`, `get_eisenhower`,
  `create_eisenhower`, `update_eisenhower`, `delete_eisenhower`).
  Stored as markdown files in `eisenhower/` with quadrant arrays in
  frontmatter.
- Mindmap domain (v2): full stack — types, repository, service, API CRUD
  at `/api/v1/mindmaps`, SSR list view at `/mindmaps`, detail view with
  interactive SVG renderer (drag-and-drop, zoom/pan), inline edit, SSE
  refresh, and MCP tools (`list_mindmaps`, `get_mindmap`,
  `create_mindmap`, `update_mindmap`, `delete_mindmap`). Tree structure
  is encoded as indented markdown bullet lists in `mindmaps/`.
- Contacts domain (v2): full stack — types, repository, service, API CRUD
  at `/api/v1/contacts`, SSR list view at `/contacts` (card + table
  views, type/company filters, multi-field search), detail page, SSE
  live swap, and MCP tools (`list_contacts`, `get_contact`,
  `create_contact`, `update_contact`, `delete_contact`). Stored as
  markdown files in `contacts/` with type enum (lead, customer, partner,
  vendor, other), tags, and freeform notes.

### Added (patch)

- Bulk action bar: tag input with Add/Remove buttons — type a tag and press
  Enter (or click Add tag) to add it to all selected tasks; click Remove tag
  to strip it from all selected tasks.
- Keyboard shortcut `t` toggles dark/light theme when no input is focused
  (mirrors existing button behavior).

### Added (patch)

- Mindmap edit textarea: Tab indents (single line or every line in a
  multi-line selection); Shift+Tab outdents. 2-space step matches the
  bullet-tree format the parser/serializer require.
- Date range filter (all list views): every domain list page now shows a
  "Created after" / "Created before" date range filter in the collapsible
  filter panel, narrowing the list to records created within the range. The
  factory applies it universally — no per-domain configuration. Domains that
  filter on a domain-specific date (meetings, finance) keep their own field.

### Fixed (patch)

- Mindmap detail view: SVG renders immediately after Save — the htmx swap
  no longer leaves the canvas blank. `mindmap.js` now re-initializes on
  `htmx:afterSettle` (dedupe via `data-mindmap-initialized` flag on the
  container) and is loaded in edit mode so the post-save swap finds it.
- Milestone detail view: links and all other fields update live after editing
  via `SseRefresh` wired to `sse:milestone.updated`.
- `parseFormBody` (`clearEmpty: true`) now passes `null` for empty fields so
  `mergeFields` applies the clear. Previously it passed `undefined`, which
  `mergeFields` silently skips — making it impossible to clear any optional
  field via edit forms across all domains.
- Identity select in topbar now vertically centers with `align-self: center`.
- Focused task row (`j`/`k` navigation) uses `box-shadow` instead of
  `outline` to avoid layout shift.
- Bulk action bar uses `overflow-x: auto` instead of `flex-wrap` so actions
  stay on one line on narrow viewports.
- SWOT quadrant header has `flex-shrink: 0`; quadrant list has
  `overflow-y: auto` to prevent overflow on small screens.
- Lean Canvas detail view: added edit mode (`?editing=true`) with per-item
  add/edit/remove on each of the 12 canvas sections, mirroring the Business
  Model Canvas pattern. The section textareas were removed from the create/
  edit sidenav — `parseFormBody` saved them as raw strings, which the
  repository serializer then iterated character-by-character, corrupting the
  saved data into single-character bullets.
- Fishbone detail view: added edit mode (`?editing=true`) with per-item
  add/edit/remove on each cause category, plus add/rename/delete of whole
  categories. Mirrors the SWOT quadrant-edit pattern. Previously the module
  was read-only after creation — causes could not be edited at all, and a
  newly created fishbone (which starts with zero categories) was unusable.
- Retrospective detail view: added edit mode (`?editing=true`) with per-item
  add/edit/remove on the Continue / Stop / Start sections. Those sections were
  removed from the create/edit sidenav — `parseFormBody` saved a textarea as a
  raw string which the repository serializer corrupted into single-character
  bullets (same root cause as Lean Canvas and Fishbone). Participants are now a
  People-linked autocomplete (`tags` + `source: "people"`) instead of a
  one-per-line textarea.
- Retrospective was unreadable after its first save (`GET /:id/edit` → 404,
  edit sidenav would not reopen). `RETROSPECTIVE_BODY_KEYS` listed `id`,
  `date`, and `status` as body keys, so `serialize()` wrote them to neither
  the frontmatter nor the body — `date`/`status` were lost on every update —
  and `parse()` then rejected the rewritten file because its guard required a
  frontmatter `id`/`title`. Body keys are now just `title` + the three
  sections; `parse()` also accepts a file identified by its `# heading`.
- SWOT, Lean Canvas, Business Model, and Retrospective carried four
  near-identical copies of the inline section-edit routes (detail page +
  add/edit/remove handlers). Consolidated into one `registerSectionEditRoutes`
  factory; SWOT and Retrospective now share a `QuadrantEditGrid` view
  component. The Lean Canvas / Business Model PUT handler also stopped
  returning a bare 204 — every mutation now re-renders the detail page.
- Reflection detail view: aligned to the canonical edit-mode pattern
  (`?editing=true`). Structured fields (title, period, date, template ID,
  tags) edit via the sidenav; the long-form `content` now edits in place via
  an "Edit Mode" toggle with an explicit Save button, instead of inside the
  sidenav. Mirrors the Journal reference implementation.
- Marketing Plan detail view: aligned to the canonical edit-mode pattern
  (`?editing=true`). Structured fields (name, status, budget, dates, project,
  responsible, team, audiences, channels, campaigns, hypothesis, learnings,
  linked goals) edit via the sidenav; the long-form `description` and `notes`
  now edit in place via an "Edit Mode" toggle with an explicit Save button per
  field (`PUT /marketing-plans/:id/description`, `PUT /marketing-plans/:id/notes`),
  instead of inside the dense sidenav form. Mirrors the Journal reference
  implementation.
- Onboarding detail view: steps can now be managed from the UI. Each step has
  a completion checkbox (toggles complete / not-started) and an inline-editable
  title with an explicit Save button; both persist via htmx POSTs that
  re-render the page and publish `onboarding.updated`. The progress bar now
  renders correctly with the native `<progress>` element — previously it used
  a `<div class="progress-bar__fill" data-pct>` markup that had no CSS or JS
  backing it, so the bar was always empty. Steps were otherwise read-only with
  no progress tracking.
- Portfolio detail view: surfaces three previously stored-but-invisible fields.
  `logo` now renders as a small image inside the title row; `billingCustomerId`
  resolves to the customer name (linked to `/customers/:id`, falls back to the
  raw ID if the customer was deleted); `brainManaged` shows as a Yes/No
  `<InfoItem>`. Both new info entries live in a guarded `.detail-info-row`
  matching the `company-detail` pattern. Detail route now fetches the customer
  alongside goals + people in a single `Promise.all`.
- Portfolio `client` field is now a Customer autocomplete (form +
  detail-page link) instead of free text. The create/edit form uses
  `AutocompleteWidget` against the `customers` source and stores the
  selected customer's ID. The detail page meta line resolves that ID via
  `getCustomerService().getById()` (in the same `Promise.all` as
  `billingCustomerId`) and renders the customer name as a link to
  `/customers/:id`; legacy free-text values (e.g. "Internal", "Multiple")
  still render as plain text when the value does not resolve to a
  customer. Schema unchanged (`client: string | null | undefined`) —
  accommodates both new IDs and legacy names without a migration.
- Business Model and Lean Canvas detail views (edit mode): each `.lc-section`
  is now bounded by `--lc-section-edit-max-h` (40vh) and its items list
  scrolls internally, so the "Add item" input stays anchored at the bottom
  of the section regardless of how many items the section holds. Previously
  long sections (20+ items) pushed the add input below the viewport with no
  way to scroll inside the panel. The rule is scoped via the canonical
  `[class*="-detail--editing"]` ancestor selector and only fires in edit
  mode; view mode is unchanged.
- Retrospective participants resolve to Person detail links more reliably:
  the name → Person lookup now tries exact match, then case-insensitive,
  then first-word match (so a participant entered as "Alice Martin" links
  to a Person record named "Alice" — the common drift between long-form
  participant names and short-name Person records). Ambiguous first-word
  matches fall back to plain text instead of mis-linking. The resolver lives
  in `v2/utils/person-name-match.ts` and is shared with the Person detail
  view (see next entry).
- Person detail page now lists every retrospective the person participated
  in under a new "Retrospectives" section (after Direct reports), each item
  a link to the retro with its date. Membership is determined by the same
  tolerant name matcher used on the retrospective detail page, so the two
  views agree on who is linked.
- Onboarding: the record had no way to identify who is being onboarded, and
  steps had no way to record who owns each step — the module was unusable
  for real onboarding flows. The create/edit form now exposes the existing
  `personId` field as an "Onboardee" autocomplete (people source, stores
  ID) and ships a steps array-table where each row carries an "Owner"
  autocomplete. The detail page resolves both IDs to names and links to
  `/people/:id`. Step IDs and statuses round-trip through the form via
  hidden item-fields (new `hidden` variant in `ArrayTableItemField`), so
  the in-place checkbox/title editors keep working after a sidenav save.
- Note detail page: title was visually clipped to roughly 240 px. The header
  uses `flex-direction: column`, but `align-items: flex-start` was cascading
  in from `.detail-header` (components.css), so `.detail-title-row` hugged
  fit-content and the inline-edit `<input>` (with `width: 100%`) collapsed to
  its UA-default size. Added `align-items: stretch` to `.note-detail__header`
  so the title input fills the full header width.
- Note detail page: removed the always-on "Updated <X> ago" span from the
  header `.note-detail__meta`. It was a duplicate of the canonical
  `AuditMeta` footer (which already shows the updated timestamp) and gave
  the misleading impression of a permanent save indicator. Save confirmation
  is already covered by the global toast wired through `HX-Trigger` on
  `POST /notes/:id/title` and `POST /notes/:id/project`.

### Changed

- Factory toolbar: the sort-reset control was a filled `btn--tertiary` pill
  labelled `✕ Sort` that looked like a one-off across every list view.
  Restyled to a ghost `btn--ghost btn--sm` pill labelled `↺ Clear sort`
  (with `aria-label`/`title`) so it matches the right-side toolbar
  vocabulary (view toggle, column toggle). Behavior unchanged — the
  button still GETs `/<domain>/view?sort=&order=` and only renders when
  `state.sort` is active.
- `UpdateProjectConfigSchema` now accepts all project.md fields (startDate,
  workingDaysPerWeek, workingDays, tags, links) instead of only name,
  description, and features.
- `ProjectService.updateConfig` applies all schema fields.
- `enabledFeatures` threaded through all view routes and layout components.
