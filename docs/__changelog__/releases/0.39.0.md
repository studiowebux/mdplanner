### Added

- Settings page (v2): tabbed layout with five sections — Views, Project,
  Schedule, Tags, Links. All project.md fields are now editable from the UI.
- Settings Views tab: enabled/disabled collapsible groups, search filter,
  check all/uncheck all bulk actions.

  values revert to their original state. Dirty tabs show a warning dot and
  `beforeunload` prevents accidental navigation.
- OpenAPI (Scalar): vendored API reference at `/api/v1/reference` with
  documented schemas for all Settings, Milestone, and Portfolio endpoints.
- OpenAPI model names: all Zod schemas now register `.openapi("Name")` so
  they appear in the Swagger Models section (Task, FeaturesList,
  UpdateProjectConfig, ProjectLink, etc.).
- MCP server (v2): scaffold at `/mcp` with 7 milestone tools as thin
  wrappers over shared services. Service-first architecture with unified
  Zod schemas.
- Sidebar: dynamic navigation built from enabled features list. Toggling
  features in Settings immediately refreshes the sidebar.
- Eisenhower domain (v2): full stack — types, repository, service, API
  CRUD at `/api/v1/eisenhower`, SSR matrix view at `/eisenhower`, detail
  page, SSE live swap, and MCP tools (`list_eisenhower`, `get_eisenhower`,
  `create_eisenhower`, `update_eisenhower`, `delete_eisenhower`).
  Stored as markdown files in `eisenhower/` with quadrant arrays in
  frontmatter.

  at `/api/v1/mindmaps`, SSR list view at `/mindmaps`, detail view with

  refresh, and MCP tools (`list_mindmaps`, `get_mindmap`,
  `create_mindmap`, `update_mindmap`, `delete_mindmap`). Tree structure
  is encoded as indented markdown bullet lists in `mindmaps/`.
- Contacts domain (v2): full stack — types, repository, service, API CRUD
  at `/api/v1/contacts`, SSR list view at `/contacts` (card + table
  views, type/company filters, multi-field search), detail page, SSE
  live swap, and MCP tools (`list_contacts`, `get_contact`,
  `create_contact`, `update_contact`, `delete_contact`). Stored as
  markdown files in `contacts/` with type enum (lead, customer, partner,
  vendor, other), tags, and freeform notes.

### Fixed (patch)

- Note editor spacing: the add-block toolbar sat flush against the first block
  and each block's controls sat directly on its textarea. The toolbar is
  inserted before `.note-detail__body` (so the body's block `gap` never applied
  to it) and `.note-editor__block` had no styling. Added `margin-bottom` on the
  toolbar and made each editable block a `flex` column with a `gap`, removing the
  ad-hoc `padding-bottom` on the controls so spacing comes from one mechanism.
- Note editor: the per-block **Preview** button now renders into its preview
  pane. The edit-mode SSE guard attached an `htmx:beforeRequest` listener to the
  `<main>` SSE element that cancelled the request whenever `editing` was true —
  but `htmx:beforeRequest` bubbles, so it also cancelled the Preview button's
  own POST (the one case that only runs while editing). The guard now cancels
  only the SSE element's own live-refresh request (`e.target === sse`), letting
  descendant requests through while still protecting the open editor from
  SSE-driven re-render.
- Topbar dropdowns (project/assignee global filters, person switcher, search)
  could be painted over by a page's sticky table/list header (most visibly on
  the capacity-plans list). Two-part cause: the topbar was `static` with no
  stacking context, and — the flaky part — a `position: sticky` `<thead>` gets
  promoted to its own GPU/composited layer and could paint over the topbar
  dropdown even with a lower z-index, until some unrelated repaint corrected it
  (which is why opening the person menu first "fixed" the filter popup). The
  topbar now owns a stable stacking context at the new `--z-topbar` tier (100 —
  above every content sticky layer, below the mobile menu/overlay) AND is forced
  onto its own composited layer (`transform: translateZ(0)`) so the layer order
  is correct from first paint. Single shell-level fix; no per-table change.
- Topbar popups are now mutually exclusive: opening a global filter closes the
  person switcher and vice versa, so two topbar dropdowns can no longer be open
  at the same time.
- Mindmap layout: sibling branches no longer overlap when a node has 4 or more
  children. The renderer used two disagreeing vertical-spacing formulas — a
  leaf-span of `n*NODE_H + (n-1)*V_GAP` for centering a node vs a child-advance
  of `+V_GAP*2` per node when placing siblings — so a parent reserved less
  height than its children actually consumed. The `(n-1)*V_GAP` shortfall was
  hidden by `NODE_H` slack at 3 or fewer children and overlapped at 4+. Replaced
  both with a single per-leaf pitch `ROW_PITCH = NODE_H + V_GAP`, from which
  every subtree span and sibling advance is derived, so a node's center is
  always the exact middle of its band and the layout never under-reserves. The
  pure geometry was extracted to `mindmap-layout.js` (no DOM) and is now covered
  by unit tests (`tests/v2/mindmap-layout_test.ts`).

- Example demo data: repaired dangling cross-references so the Settings → Data
  Integrity scan reports 0 errors / 0 warnings (was 5 errors + 4 warnings).
  Brainstorm `linked_projects`/`linked_goals`/`linked_tasks` pointed at v1 IDs
  dropped during migration; two billing customers referenced companies absent
  from the demo. Repointed links to real entities and added the two missing
  company records.

- Global project/assignee filter: selecting more than one project (or
  assignee) now correctly shows the union of all selected (OR), instead of
  collapsing to just the first. The topbar fired a separate `change` POST per
  click with no request serialization, so two rapid selections raced — each
  wrote the full selection it knew at send time, and whichever response landed
  last won, often a stale single-item set. Both filter wraps now share one
  `hx-sync="closest .topbar__actions:queue last"` queue, so posts run
  sequentially and the latest full-state write always wins. Fixes every domain
  using the shared global filter (18 domains); the assignee filter, which had
  the same race, now holds reliably too.

- Analytics light-mode layout: the 13 `--analytics-*` layout tokens
  (`--analytics-chart-max-h`, `--analytics-stat-card-min-w`,
  `--analytics-kpi-card-min-w`, `--analytics-chart-label-size`,
  `--analytics-col-min-w`, `--analytics-util-bar-h`,
  `--analytics-by-value-min-w`, `--analytics-details-content-pad`, etc.)

  `max-height: var(--analytics-chart-max-h)` silently dropped, leaving chart

  theme-independent dimensions; moved them into base `:root {}` alongside the
  already-correct `--analytics-progress-scroll-max-h`. CSS-only change.

- Deals pipeline view visual polish: the kanban-style board no longer
  reads as "amateur". Owner-pill ("Tommy") no longer stretches to card
